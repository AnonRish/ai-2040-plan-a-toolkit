# Plan A integration map

The four tracks from the AI Futures Project verification roadmap are maintained
as separate engineering surfaces but exchange compatible machine-readable
evidence concepts.

Track 1 lives primarily in this toolkit: embedded audit challenges, evidence
hash chains, threshold receipts and safe protocol red-team tests.

Track 2 lives primarily in Frontier Verify plus the AI 2040 verification
prototype. The experimental v2 API now runs the complete software sequence:
challenge commitment, full claim submission, content-addressed inputs,
randomized selection, deterministic recomputation, mismatch classification and
signed receipt.

Track 3 lives primarily in Continental Load Registry. Its public-data pipeline
already retains source, physical-observation and evidence-accounting layers; the
new residual-bound engine only returns a numeric global bound for an explicitly
closed population with complete independent site capacity inputs. The current
public population remains open, so the current residual remains UNKNOWN.

Track 4 lives primarily here and in the existing AI 2040 verification prototype.
The workload manifest binds code/model/data/runtime/compiler identities to
allowed operations and resource limits and returns PASS/FAIL/UNKNOWN. This is
the software boundary; frontier-scale cryptographic proof is still a research
problem.

## Evidence contract

Across all tracks, the intended conceptual chain is:

Observation -> Evidence -> Claim -> Verification procedure -> Result -> Attestation -> Receipt

No missing observation is silently converted into evidence of absence.
